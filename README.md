# ai-reviewer — AI code review для PR (7Hills)

Ревьюит Pull Request через Claude API (кредиты подписки Team) и оставляет:
- **inline-замечания** на строках диффа (🔴 критично / 🟠 важно / 🟡 желательно);
- **одну сводку** в PR (обновляется при повторном запуске, не плодится).

Модель сама ходит по репозиторию: читает файлы целиком, ищет вызовы, сравнивает с базовой веткой, читает правила проекта (контракты, конвенции, инструкции ревью).

## Безопасность

- Только чтение. `.env`, ключи, `.git` недоступны модели — в том числе через symlink, добавленный в PR. Секретные файлы не попадают и в дифф, который уходит в API.
- Конфиг `.github/ai-review.json` и файлы правил читаются **из базовой ветки**, а не из PR: PR не может ослабить свои правила, сменить модель или поднять лимит. Поэтому новый конфиг начинает действовать после мержа в базовую ветку.
- Лимиты зашиты в код: не больше $10 и 40 ходов на ревью, модель — только из списка.
- PR из форков не ревьюятся. `/ai-review` срабатывает только от OWNER/MEMBER/COLLABORATOR.
- Токен checkout не сохраняется на диске (`persist-credentials: false`).
- В API уходит исходный код проекта (не данные заказчиков из БД). Для репозиториев, где код нельзя передавать за пределы РК, ревьюер не подключать.

## Подключение проекта (2 файла)

1. `.github/workflows/ai-review.yml` — скопировать из `examples/ai-review.yml`.
2. `.github/ai-review.json` — правила проекта (необязательно, но сильно повышает качество). Пример — `examples/ai-review.example.json`.

Секрет `ANTHROPIC_API_KEY` — один раз на организацию (Settings → Secrets and variables → Actions → Organization secrets) или в репозиторий.

## Когда запускается

| Событие | Ревью |
|---|---|
| PR открыт / переоткрыт / снят с draft | да |
| Комментарий `/ai-review` в PR (от участника репо) | да, повторно |
| Метка `ai-review` на PR | да |
| Новый push в PR | нет — чтобы не жечь кредиты; перезапуск через `/ai-review` |

Повторный запуск не дублирует уже оставленные inline-замечания. Если GitHub отклонил замечание (строка вне диффа), оно попадает в сводку, а не теряется.

## Конфиг `.github/ai-review.json`

| Поле | По умолчанию | Что это |
|---|---|---|
| `model` | `claude-opus-5-5` | `claude-sonnet-5-5` — дешевле в 2 раза |
| `effort` | `high` | `medium` — быстрее и дешевле |
| `maxCostUsd` | `3` | Жёсткий лимит на одно ревью |
| `minSeverity` | `minor` | `nit` — показывать и мелочи |
| `maxInlineComments` | `20` | Остальное уходит в сводку |
| `instructions` | `[]` | Файлы правил, которые модель получает целиком всегда |
| `guides` | `[]` | `{path, when}` — доки, которые модель читает по необходимости |
| `notes` | `""` | Свободный текст о проекте |
| `ignore` | lock-файлы, dist, картинки… | Доп. glob-и, которые не ревьюим |

Общие стандарты 7Hills — в `prompts/base.md` (меняются в одном месте для всех проектов).

## Стоимость

Типичный PR на Opus 5.5 — $0.3–1.5 (кэширование промпта включено). Стоимость каждого ревью видна внизу сводки. Месячный пул кредитов Team — до $500, сгорает в конце цикла.

## Локальная проверка

```bash
npm test                                             # юнит-тесты, без сети
node src/index.mjs --local --repo ../my-project \
  --base origin/develop --head feature/xxx --mock    # прогон без API
ANTHROPIC_API_KEY=... node src/index.mjs --local \
  --repo ../my-project --base origin/develop --head feature/xxx --out review.md
```

Локально конфиг тоже берётся из базового коммита; `--trust-head` — взять из ветки (для отладки нового конфига), `--config /abs/path.json` — явный файл.

## GitLab

Ядро не зависит от GitHub, кроме `src/github.mjs` и `runAction()` в `src/index.mjs`. Для GitLab CI нужен аналогичный адаптер (MR notes + discussions API) — при переезде.
